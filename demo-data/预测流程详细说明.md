## 概述

本系统采用**两阶段预测架构**进行漏洞风险评估：

- **Stage A (适用性门控)**: 判断输入文本是否与漏洞相关，过滤非漏洞相关文本
- **Stage B (严重度评估)**: 对通过Stage A的文本进行4类严重度分类（Low/Medium/High/Critical）

系统还包含**保守的系统级处理机制**，确保在论文答辩演示中行为可靠。

## 单个预测流程

### 1. 前端提交

**位置**: `frontend-vue/src/views/Predictions.vue`

**用户操作**:
1. 打开 Predictions 页面
2. 点击 "Single Prediction" 按钮
3. 填写表单：
   - **Sample ID**: 样本标识符（必需）
   - **Text Description**: 文本描述（必需）
   - **CVSS Base Score**: CVSS基础评分（可选，0-10）

**表单验证**:
- `sample_id` 和 `text_description` 为必填项
- `cvss_base_score` 为可选，范围 0-10

### 2. 后端接收与处理

**位置**: `backend-node/src/controllers/prediction.controller.ts`

**API端点**: `POST /api/predictions`

**处理步骤**:
1. 接收请求体：
   ```json
   {
     "sample_id": "POS-001",
     "text_description": "A remote code execution vulnerability...",
     "cvss_base_score": 7.5
   }
   ```

2. 验证必填字段（`sample_id`, `text_description`）

3. 调用 `PredictionService.predict()` 方法

### 3. 模型服务调用

**位置**: `backend-node/src/services/prediction.service.ts`

**处理步骤**:
1. **获取激活的Stage A模型**:
   - 从数据库查询 `isActive=true` 且 `id` 不以 `sev_model_` 开头的模型
   - 如果指定了 `modelId`，使用指定模型
   - 如果未找到模型，抛出错误

2. **构建ML服务请求**:
   ```json
   {
     "model_path": "/app/models/app_model_002_aug_xgb",
     "sample": {
       "sample_id": "POS-001",
       "text_description": "A remote code execution vulnerability...",
       "cvss_base_score": 7.5
     }
   }
   ```

3. **调用ML服务**: `POST http://ml-service:5000/predict`

### 4. ML服务两阶段预测

**位置**: `ml-service/app.py`

**处理流程**:

#### 步骤1: 文本预处理
- 转换为小写
- 移除特殊字符
- 标准化空白字符
- 结果: `processed_text`

#### 步骤2: 输入质量检查（Precheck）
- **函数**: `check_input_quality(text_description, processed_text)`
- **检查项**:
  - 文本长度（过短或过长）
  - 重复性（高度重复的文本）
  - 语义结构（是否有意义的内容）
- **如果质量低**:
  - 返回 `applicable=False`
  - `pApplicable=0.0`
  - `severityLevel='N/A'`
  - `reliability='Low'`
  - 添加质量说明到 `notes`

#### 步骤3: Stage A - 适用性判断
- **加载模型**: `app_model_002_aug_xgb` (XGBoost)
- **特征提取**: TF-IDF向量化（使用训练时的vectorizer）
- **预测**: `pApplicable = model.predict_proba(X)[0, 1]`
- **阈值判断**: `applicable = pApplicable >= 0.5` (默认阈值)

**如果 `applicable=False`**:
- 返回结果，不进入Stage B
- `severityLevel='N/A'`
- `severityProbs=None`
- `riskScore=None`

#### 步骤4: 证据充分性检查（保守门控）
- **函数**: `extract_evidence(text_description, processed_text)`
- **统计**:
  - `security_keyword_count`: 安全关键词数量（XSS, SQLi, RCE等）
  - `context_cue_count`: 上下文线索数量（exploit, attacker, remote等）
  - `technical_evidence_count`: 技术证据数量（CVE ID, 版本号, 堆栈跟踪等）
- **判断**: 如果 `security_keyword_count > 0` 但 `context_cue_count + technical_evidence_count < 1`
- **如果证据不足**:
  - 返回 `applicable=False`
  - 添加说明: "Security keywords detected but insufficient exploit/impact/context evidence"

#### 步骤5: Stage B - 严重度评估
- **加载模型**: `sev_model_001` (XGBoost)
- **特征提取**: TF-IDF向量化（使用训练时的vectorizer）
- **预测**: 4类概率分布
  ```python
  severity_probs = {
    'Low': 0.15,
    'Medium': 0.25,
    'High': 0.35,
    'Critical': 0.25
  }
  ```
- **确定严重度**: `severityLevel = argmax(severity_probs)` → `'High'`
- **计算风险评分**: 
  ```python
  riskScore = 0.1 * P(Low) + 0.4 * P(Medium) + 0.7 * P(High) + 0.9 * P(Critical)
  ```
- **计算P(High+)**: `pVuln = P(High) + P(Critical)` (兼容字段)

#### 步骤6: 补丁/缓解文本检测
- **函数**: `detect_patch_mitigation_text(text_description, processed_text)`
- **检测模式**: 
  - 前缀: "Fix:", "Patch:", "Hotfix:", "Security:"
  - 动词: "prevent", "mitigate", "sanitize", "escape", "validate"
- **如果检测到**:
  - `inputType='patch_mitigation'`
  - 降级可靠性: `reliability = downgrade_reliability(reliability, 'PATCH_MITIGATION')`
  - 添加说明到 `notes`

#### 步骤7: 不确定性评估
- **函数**: `assess_prediction_uncertainty(severity_probs)`
- **评估指标**:
  - Top-1和Top-2概率差距（margin < 0.15 认为不确定）
  - 概率分布熵（接近均匀分布认为不确定）
  - 最大概率是否足够高（< 0.4 认为不确定）
- **如果不确定**:
  - 降级可靠性: `reliability = downgrade_reliability(reliability, 'UNCERTAINTY')`
  - 添加说明到 `notes`

#### 步骤8: 构建返回结果
```python
{
  'applicable': True,
  'pApplicable': 0.95,
  'severityLevel': 'High',
  'severityProbs': {
    'Low': 0.15,
    'Medium': 0.25,
    'High': 0.35,
    'Critical': 0.25
  },
  'riskScore': 0.72,
  'pVuln': 0.60,  # P(High) + P(Critical)
  'riskLevel': 'High',  # 兼容字段
  'explanation': 'Vulnerability-related text detected. Predicted severity: High...',
  'reliability': 'Medium',
  'notes': ['Prediction uncertainty is high...'],  # 如果有
  'inputType': 'normal',  # 或 'patch_mitigation'
  'modelInfo': {
    'applicabilityModel': 'app_model_002_aug_xgb',
    'severityModel': 'sev_model_001'
  }
}
```

### 5. 后端保存与返回

**位置**: `backend-node/src/services/prediction.service.ts`

**处理步骤**:
1. **解析ML服务响应**: 提取所有字段
2. **保存到数据库**:
   ```typescript
   {
     modelId: model.id,
     sampleId: input.sample_id,
     textDescription: input.text_description,
     pVuln: finalPVuln,
     cvss: finalCvss,
     riskScore: finalRiskScore,
     riskLevel: finalRiskLevel,
     explanation: explanation,
     metadata: {
       // 包含所有扩展字段
       pApplicable, applicable, severityLevel, severityProbs,
       reliability, notes, inputType, modelInfo, ...
     }
   }
   ```
3. **返回给前端**: 包含所有字段的完整预测结果

### 6. 前端显示

**位置**: `frontend-vue/src/views/Predictions.vue`

**显示内容**:
- 预测结果添加到列表
- 可以点击 "View" 查看详细报告
- 列表显示: Sample ID, Text Description, P(Applicable), P(High+), Risk Score, Risk Level, CVSS, Created At

## 批量预测流程

### 1. 文件上传

**位置**: `frontend-vue/src/views/Predictions.vue`

**用户操作**:
1. 点击 "Batch Import" 按钮
2. 选择 "Upload File" 标签
3. 上传CSV/JSON/Excel文件

**支持的文件格式**:
- CSV (`.csv`)
- JSON (`.json`)
- Excel (`.xlsx`, `.xls`)

**文件格式要求**:
- 必需字段: `sample_id` (或 `sampleId`, `Sample ID` 等变体)
- 必需字段: `text_description` (或 `textDescription`, `Text Description` 等变体)
- 可选字段: `cvss_base_score`

### 2. 后端文件解析

**位置**: `backend-node/src/services/prediction.service.ts`

**处理步骤**:
1. **接收文件**: 通过 `multer` 中间件接收上传文件
2. **解析文件**: `parseFileToSamples(filePath, originalName)`
   - CSV: 使用 `csv-parse` 解析
   - JSON: 支持数组格式或 `{"samples": [...]}` 格式
   - Excel: 使用 `xlsx` 库解析
3. **字段映射**: 支持多种字段名变体（不区分大小写）
4. **验证**: 确保每个样本都有 `sample_id` 和 `text_description`

### 3. 批量调用ML服务

**位置**: `backend-node/src/services/prediction.service.ts`

**处理步骤**:
1. **构建ML服务请求**:
   ```json
   {
     "model_path": "/app/models/app_model_002_aug_xgb",
     "samples": [
       {
         "sample_id": "POS-001",
         "text_description": "...",
         "cvss_base_score": 7.5
       },
       {
         "sample_id": "POS-002",
         "text_description": "..."
       }
     ]
   }
   ```

2. **调用ML服务**: `POST http://ml-service:5000/predict/batch`
   - 超时时间: 5分钟

### 4. ML服务批量预测

**位置**: `ml-service/app.py`

**处理流程**:
- 对每个样本依次调用 `predict_two_stage()` 函数
- 处理逻辑与单个预测完全相同
- 返回所有样本的预测结果数组

### 5. 批量保存与返回

**位置**: `backend-node/src/services/prediction.service.ts`

**处理步骤**:
1. **批量保存**: 使用 `Promise.all()` 并行保存所有预测结果到数据库
2. **返回结果**:
   ```json
   {
     "predictions": [
       { /* 预测结果1 */ },
       { /* 预测结果2 */ },
       ...
     ],
     "count": 15
   }
   ```

### 6. 前端显示

**位置**: `frontend-vue/src/views/Predictions.vue`

**显示内容**:
- 所有预测结果添加到列表
- 可以分页查看
- 可以导出为CSV/Excel/JSON

## 两阶段预测机制

### Stage A: 适用性门控

**目的**: 过滤非漏洞相关文本，只对漏洞相关文本进行严重度评估

**模型**: `app_model_002_aug_xgb` (XGBoost)

**训练数据**:
- **正类**: CVE漏洞描述（从 `merged_json_table.csv`）
- **负类**: 
  - GitHub工程问题（从 `negative_github_issues.csv`）
  - 噪声文本（`neg_noise.csv`）
  - 关键词但无上下文（`neg_keyword_only.csv`）
  - 补丁/缓解文本（`neg_patch_mitigation.csv`）

**输出**:
- `pApplicable`: 适用性概率 [0, 1]
- `applicable`: 布尔值（`pApplicable >= 0.5`）

**决策逻辑**:
- 如果 `applicable=False`: 不进入Stage B，返回N/A结果
- 如果 `applicable=True`: 进入Stage B进行严重度评估

### Stage B: 严重度评估

**目的**: 对通过Stage A的文本进行4类严重度分类

**模型**: `sev_model_001` (XGBoost)

**训练数据**: CVE漏洞描述，标注为4类严重度（Low/Medium/High/Critical）

**输出**:
- `severityProbs`: 4类概率分布
  ```json
  {
    "Low": 0.15,
    "Medium": 0.25,
    "High": 0.35,
    "Critical": 0.25
  }
  ```
- `severityLevel`: 最大概率对应的严重度等级
- `riskScore`: 加权风险评分 [0, 1]
  ```python
  riskScore = 0.1 * P(Low) + 0.4 * P(Medium) + 0.7 * P(High) + 0.9 * P(Critical)
  ```
- `pVuln`: P(High) + P(Critical) (兼容字段)

## 系统级处理机制

### 1. 输入质量检查（Precheck）

**触发条件**:
- 文本过短（< 10字符）
- 文本过长（> 5000字符）
- 高度重复（重复率 > 80%）
- 无语义结构

**处理结果**:
- `applicable=False`
- `pApplicable=0.0`
- `severityLevel='N/A'`
- `reliability='Low'`
- `notes`: 质量说明

### 2. 证据充分性检查（保守门控）

**触发条件**:
- 检测到安全关键词（XSS, SQLi等）
- 但上下文线索和技术证据不足（`context_cue_count + technical_evidence_count < 1`）

**处理结果**:
- `applicable=False`
- `pApplicable`: 保留Stage A的预测值
- `severityLevel='N/A'`
- `reliability='Low'`
- `notes`: "Security keywords detected but insufficient exploit/impact/context evidence"

### 3. 补丁/缓解文本检测

**触发条件**:
- 文本包含补丁/缓解关键词（Fix:, Prevent:, Mitigate:, Sanitize等）

**处理结果**:
- `inputType='patch_mitigation'`
- `reliability`: 降级一级（High→Medium, Medium→Low）
- `notes`: 添加补丁/缓解说明
- **不改变** `severityLevel` 和 `severityProbs`（保持模型预测）

### 4. 不确定性评估

**触发条件**:
- Top-1和Top-2概率差距 < 0.15
- 概率分布熵过高（接近均匀分布）
- 最大概率 < 0.4

**处理结果**:
- `reliability`: 降级一级
- `notes`: 添加不确定性说明
- **不改变** `severityLevel` 和 `severityProbs`（保持模型预测）

## 不同输入类型的预期结果

### 1. 正类样本（CVE漏洞描述）

**示例**: `POS-001` - "A remote code execution vulnerability exists..."

**预期结果**:
- `applicable=true`
- `pApplicable >= 0.5` (通常 > 0.8)
- `severityLevel`: Low/Medium/High/Critical（根据漏洞类型）
- `severityProbs`: 4类概率分布
- `riskScore`: 根据严重度计算
- `reliability`: Medium 或 High
- `inputType`: "normal"

### 2. 负类样本（普通工程问题）

**示例**: `NEG-001` - "The login button does not respond..."

**预期结果**:
- `applicable=false`
- `pApplicable < 0.5` (通常 < 0.3)
- `severityLevel='N/A'`
- `severityProbs=null`
- `riskScore=null`
- `reliability='Low'`
- `explanation`: "Text appears not vulnerability-related..."

### 3. 噪声样本

**示例**: `AUG-NOISE-001` - "hello hello, nice to meet you"

**预期结果**:
- `applicable=false`
- `pApplicable < 0.3`
- `severityLevel='N/A'`
- `reliability='Low'`
- `notes`: 质量检查说明

### 4. 关键词但无上下文样本

**示例**: `AUG-KW-001` - "TODAY IS A GOOD DAY XSS"

**预期结果**:
- `applicable=false` (证据充分性检查触发)
- `pApplicable`: 可能 > 0.5（Stage A可能通过）
- `severityLevel='N/A'` (保守门控拒绝)
- `reliability='Low'`
- `notes`: "Security keywords detected but insufficient exploit/impact/context evidence"

### 5. 补丁/缓解文本样本

**示例**: `AUG-PATCH-001` - "Fix: Prevent command injection..."

**预期结果**:
- `applicable=true` (可能，因为包含安全关键词)
- `pApplicable >= 0.5` (可能)
- `severityLevel`: 可能有预测值（但应保守解释）
- `reliability`: 降级（High→Medium, Medium→Low）
- `inputType='patch_mitigation'`
- `notes`: "This text appears to describe remediation..."

## 数据存储与查询

### 数据库存储

**表**: `predictions`

**字段**:
- `id`: UUID
- `modelId`: 模型ID（外键）
- `sampleId`: 样本ID
- `textDescription`: 文本描述
- `pVuln`: P(High) + P(Critical)
- `cvss`: CVSS评分
- `riskScore`: 风险评分
- `riskLevel`: 风险等级
- `explanation`: 解释说明
- `metadata`: JSON字段（包含所有扩展字段）
- `createdAt`: 创建时间

### 查询接口

**获取所有预测**: `GET /api/predictions?limit=20&offset=0`

**获取单个预测**: `GET /api/predictions/:id`

**导出预测**: `GET /api/predictions/export?format=csv&limit=100&offset=0`

## 总结

### 预测流程特点

1. **两阶段架构**: Stage A过滤 + Stage B评估
2. **保守处理**: 多层门控确保可靠性
3. **详细结果**: 包含概率分布、可靠性、说明等
4. **向后兼容**: 支持旧模型和旧字段

### 演示建议

1. **先演示负类拒绝**: 展示Stage A正确过滤非漏洞文本
2. **再演示正类评估**: 展示Stage B的4类严重度预测
3. **展示鲁棒性**: 使用增强负类样本展示系统保守处理
4. **解释可靠性**: 说明 `reliability` 和 `notes` 字段的作用
